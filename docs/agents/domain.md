# Domain docs

This repository has one shared context in root `CONTEXT.md`. Lasting architectural decisions belong in `docs/adr/`.

Before exploring or changing an area, read `CONTEXT.md` and relevant ADRs. If no ADRs exist, continue without creating placeholders. Use glossary terms in issues, specs, code proposals, and tests. When a concept is missing, resolve its meaning before adding it to the glossary. If work conflicts with an ADR, surface the conflict explicitly. Add ADRs only for lasting decisions that merit a record.
