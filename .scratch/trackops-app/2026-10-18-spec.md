# TrackOps app specification

[Build spec issue #30](https://github.com/lburfeindt/trackops/issues/30).

## Problem Statement

The two music tools are separate command-line applications, and ID3 Sanitizer also has its own native app. Using them requires different entry points. Playlist titles currently appear only in terminal output. The user needs one small macOS app for both tasks, with visible progress and results, copyable playlist titles, and an explicit, safe way to save those titles.

## Solution

Ship one `TrackOps.app` with **ID3 Sanitizer** and **Format Playlist** actions. The app uses native pickers. Sanitizing starts after file or folder selection and shows progress, Stop, and counts. Formatting a playlist shows its titles in the window; the user can copy or save them. Saving creates a sibling `-formatted.txt` file and confirms replacement of an existing file. The first release is a locally built Apple Silicon app for macOS 13 or later.

## User Stories

1. As a music library owner, I want one TrackOps app for both tools, so that I can launch my music chores from one place.
2. As a music library owner, I want a small window with ID3 Sanitizer and Format Playlist actions, so that I can choose the task I need.
3. As a music library owner, I want to choose one or more MP3 files, so that I can sanitize selected tracks.
4. As a music library owner, I want to choose a folder, so that I can sanitize its MP3 files and those in subfolders.
5. As a music library owner, I want selection to start sanitizing immediately, so that I do not need another confirmation step.
6. As a music library owner, I want canceling the ID3 chooser to return to the ready window, so that no files change.
7. As a music library owner, I want to see progress while sanitizing, so that I know the app is working.
8. As a music library owner, I want to stop sanitizing between files, so that completed edits stay saved and remaining files stay untouched.
9. As a music library owner, I want updated, unchanged, and failed counts at the end, so that I know what happened, including after Stop or partial failure.
10. As a music library owner, I want individual file failures to be reported without stopping the rest of the batch, so that one bad file does not block other tracks.
11. As a music library owner, I want repeated or overlapping selections processed only once per path, so that a track is not edited twice in one batch.
12. As a music library owner, I want the existing exact `(Original Mix)` title-suffix rule preserved, so that unrelated titles and tags do not change.
13. As a music library owner, I want nonmatching and unsupported MP3 files left intact, so that sanitizing does not damage them.
14. As a playlist user, I want to choose an M3U playlist, so that I can extract its `#EXTINF` titles.
15. As a playlist user, I want titles shown in the window without writing a file, so that I can review them first.
16. As a playlist user, I want titles shown in playlist order with commas and Unicode preserved, so that the result matches the playlist.
17. As a playlist user, I want to copy the shown titles one per line, so that I can paste them elsewhere.
18. As a playlist user, I want to save the shown titles one per line, so that I can use a text file beside the playlist.
19. As a playlist user, I want the output named from the playlist stem with `-formatted.txt`, so that I can find it predictably.
20. As a playlist user, I want a Replace or Cancel choice if that output already exists, so that I control overwrites.
21. As a playlist user, I want Cancel to preserve the existing file and leave the new titles visible as Not saved, so that I can still copy or review them.
22. As a playlist user, I want a failed save to leave titles visible and the existing output intact, so that I can recover without losing data.
23. As a playlist user, I want an empty extraction to say No titles found, so that I understand the result.
24. As a playlist user, I want to save an empty result only through Save titles, so that an empty file is never created just by opening a playlist.
25. As a playlist user, I want a read error to show an error and offer another selection without Save, so that I cannot save a misleading result.
26. As a playlist user, I want canceling a later chooser to keep the current display, so that I do not lose what I was viewing.
27. As a playlist user, I want choosing another playlist to replace the display without an unsaved warning, so that switching is quick.
28. As the developer, I want to build a local macOS app with one root command, so that I can install and launch it from Finder or Spotlight.

## Implementation Decisions

- Use Wails v2 for the window and native file and folder pickers. Build one Go module for TrackOps, as decided in ADR 0001.
- Keep ID3 processing and playlist extraction as separate headless feature packages. The Wails-facing layer owns selection, progress, clipboard, save prompts, and presentation; the feature packages return structured outcomes. Keep the core callable by a future CLI.
- Preserve the existing ID3 file-editing contract: exact, case-sensitive suffix removal; nonmatching files unchanged; unrelated tag frames and audio preserved; errors leave the original intact. Preserve recursive MP3 discovery, case-insensitive extension handling, path deduplication, symlink rules, per-file failure continuation, and cancellation between files.
- Accept selected MP3 files or one folder through native pickers. Canceling selection performs no work. Show progress during the batch and final updated, unchanged, and failed counts, including canceled runs. Completed edits remain saved after Stop.
- Extract titles from M3U `#EXTINF` entries using the existing parser behavior. Show the result before any write. Copy joins titles with line breaks in display order. An empty result shows No titles found.
- Save only on **Save titles**. Strip the playlist extension and append `-formatted.txt` beside the source playlist; for example, `Set.m3u8` becomes `Set-formatted.txt`. Write one title per line. An empty result can produce an empty output file after Save.
- If the output exists, prompt **Replace** or **Cancel** before writing. Cancel leaves the output unchanged and shows Not saved. A failed save reports the error, retains the displayed titles, and leaves an existing output intact. A read error offers no Save and writes nothing.
- Choosing another playlist replaces an unsaved display without warning. Canceling the chooser keeps the current display.
- Replace the old CLI entry points, standalone ID3 GUI, and their packaging with the unified app. Adapt the root development lifecycle to the single module.
- Package one Apple Silicon `TrackOps.app` for macOS 13 or later, bundle ID `com.lburfeindt.trackops`, initial version `0.1.0`. Root `make package-macos` performs a clean Wails macOS ARM64 build, puts the bundle at `build/bin/TrackOps.app`, and ad hoc signs it for local use.

## Testing Decisions

- Test observable behavior and file effects, not framework internals or private function shape. The main seam is an automated end-to-end test through the running TrackOps window, including native pickers, prompts, clipboard, and resulting files. Keep lower-level tests for parsing and MP3 byte preservation where UI assertions cannot establish those properties reliably.
- Test the ID3 feature with temporary MP3 files: selected files and recursive folders, duplicate paths, symlinks, unchanged files, per-file failures, cancellation, and preservation of audio and unrelated tags. Existing sanitizer and batch tests provide prior art.
- Test the playlist feature with fixture and temporary files: ordered titles, commas and Unicode, empty input, read errors, copy content, output naming, successful save, replacement confirmation and cancellation, and failed replacement preserving prior output. Existing playlist parser tests provide prior art.
- Test application interactions end to end: chooser cancellation, progress and Stop, final counts, selection changes, visible titles and status, unavailable Save after read failure, and clipboard behavior. Use fixture and temporary files so each scenario can assert its resulting file state. Existing ID3 GUI tests with substituted dialogs are prior art for scenarios, though the new primary seam is the running UI.
- Run the UI suite on macOS with the Wails runtime available. Verify a packaged bundle launches on the target macOS version and that the root lifecycle targets cover the unified module.

## Out of Scope

- Windows or Linux releases and runtime verification.
- DMG, installer, Developer ID signing, notarization, and web distribution.
- New music-processing rules, backup files, or a replacement file format.
- A new CLI. The headless boundary merely keeps one possible later.
- The historical clickable window prototype as shipping UI or a test oracle for playlist saving; its auto-save behavior was superseded.
